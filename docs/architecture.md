# Train Booking App – React Native Architecture

Oct 31, 2026 · @Vinxen

## Overview & goals

The app is built with Expo + React Native (New Architecture) and organised by **feature module**. The 3D seat picker is an isolated, lazy-loaded module with a 2D fallback. Seat availability always comes from the API; the app only displays it. The backend is out of scope for this document.

Architecture principles:

- **Feature-first:** each feature (journeys, booking, seat-map-3d, tickets, auth) owns its UI, hooks, API calls and store, and exposes only its `index.ts`.
- **API is the source of truth:** the app never assumes a seat is free; every selection goes through a hold request.
- **Server state apart from UI state:** TanStack Query for API data, Zustand for UI state.
- **3D never blocks booking:** on weak devices or if the model fails, users book through the 2D seat map.
- **Tickets work offline:** QR tickets are stored on device so they scan without a connection.

      index.ts
    tickets/
    auth/
  shared/
    ui/           # Design system: Button, Card, SegmentedControl, TabBar
    api/          # HTTP client + generated OpenAPI code

Import rule: a feature never imports another feature's internals, only its `features/<name>/index.ts`. Enforce it with ESLint (`import/no-restricted-paths`).

## State & data layer

Each kind of data has exactly one home; API data is never copied into Zustand.

| Data | Home | Examples |
| --- | --- | --- |
| API data | TanStack Query | Trips, seat maps, tickets, profile |
| UI state | Zustand | Car in view, selected seat, 3D animation step |
| Persisted data | MMKV (persisted Query cache) | Tickets and QR for offline use, language |
| Secrets | expo-secure-store | Access and refresh tokens |

Query key convention:

```ts
export const qk = {
  trips: (q: TripSearch) => ['trips', q] as const,
  trip: (id: string) => ['trip', id] as const,
  seats: (tripId: string, car: number) => ['seats', tripId, car] as const,
  tickets: () => ['tickets'] as const,
};
```

Realtime events patch the cache directly with `queryClient.setQueryData(qk.seats(tripId, car), …)`, so both the 3D scene and the 2D map recolour seats without another request. After a WebSocket reconnect, the app refetches `qk.seats` to resync.

## 3D seat picker module

The train shell and interior are separate meshes: tap the train, the shell peels away, the camera moves into the car, and seats appear for selection. Booked seats are grey, free seats are white.

### Model pipeline

1. Model in Blender with fixed mesh names: `Shell_Roof`, `Shell_Left`, `Shell_Right`, `Nose`, `Interior`, `Seat` (one template seat).
2. One `.glb` per car; optimise with gltf-transform (meshopt or Draco, KTX2 textures).
3. Run gltfjsx to generate a typed TypeScript component per model.
4. Budget: under 2 MB and under 100 draw calls per car.

### Animation state machine

| State | What happens | Next |
| --- | --- | --- |
| `idle` | Whole train, gentle rotation | Tap train → `peeling` |
| `peeling` | Roof lifts, side walls slide out and fade; camera moves into the car | Animation ends → `interior` |
| `interior` | Top-down view of seat rows; pan and pinch | Tap white seat → `holding` |
| `holding` | Seat turns accent colour, waiting for the hold response | Granted → `selected`; rejected → `interior` |
| `selected` | Seat card shows (e.g. 7-E, window, Mt. Fuji side) | Continue → checkout |

Animate with `@react-spring/three` or interpolation in `useFrame`; the state lives in the module's Zustand store.

### Seats

- Render every seat with one `InstancedMesh` and colour each with `setColorAt`.
- Colours: grey = booked or held by someone else (not selectable); white = free; accent = your selection.
- Seat positions come from the API's seat layout, not the model; build the `instanceId → seatCode` array from it.
- On tap, the raycast returns `instanceId`; map it to `seatCode` and ignore it unless the seat is white.

```ts
type SeatStatus = 'available' | 'booked' | 'held';

interface SeatLayout {
  tripId: string;
  car: number;
  layout: { code: string; row: number; col: string; pos: [number, number, number]; window: boolean }[];
  status: Record<string, SeatStatus>;
  version: number; // ignore realtime events older than this
}
```

```tsx
function Seats({ layout, status }: SeatsProps) {
  const ref = useRef<THREE.InstancedMesh>(null!);
  useLayoutEffect(() => {
    layout.forEach((s, i) => {
      ref.current.setMatrixAt(i, toMatrix(s.pos));
      ref.current.setColorAt(i, colorFor(status[s.code]));
    });
    ref.current.instanceMatrix.needsUpdate = true;
    ref.current.instanceColor!.needsUpdate = true;
  }, [layout, status]);
  return (
    <instancedMesh ref={ref} args={[seatGeo, seatMat, layout.length]}
      onClick={(e) => onSeatTap(layout[e.instanceId!].code)} />
  );
}
```

### Performance and fallback

- `frameloop="demand"`: render only during animation or touch.
- Only the car in view gets the detailed interior; other cars use low LOD or an image.
- Lazy-load the seat picker so app start-up stays fast.
- A toggle switches to the 2D map; the app switches automatically if GL fails to start or FPS stays low. The 2D map is also the screen-reader path.

## Realtime & seat-hold flow

&#91;embedded content: seat-hold flow · 2 decisions\]

The app treats a seat as selected only after the hold request succeeds; a rejected hold reverts the seat and shows a short toast.

- Join the room for the current car when the seat picker opens; leave it when the screen closes.
- Handle `seat.held`, `seat.released` and `seat.booked` events by patching `qk.seats`; drop events whose `version` is older than the cached data.
- Checkout counts down from the hold's `expiresAt` returned by the API, not from the device clock.
- After payment, show the result the API confirms; never mark a ticket as booked from the payment screen alone.

## Performance, testing, CI/CD

Target: 60 fps in the seat picker on a mid-range Android phone, and an E2E test for every booking path before release.

**Performance**

- Lists use FlashList; images use expo-image with caching.
- 2D animation runs in Reanimated worklets, never per-frame React state.
- Measure 3D FPS on one fixed mid-range Android device from week one, not at the end.

**Testing**

- Unit (Jest): layout → instance mapping, the animation state machine, event version checks.
- Component (React Native Testing Library): trip card, 2D seat map, checkout.
- E2E (Maestro): search → pick seat (2D) → sandbox payment → open ticket offline.
- Hold conflicts: mock a rejected hold and assert the seat reverts to grey.

**CI/CD**

- Pull requests: lint, typecheck, unit tests, EAS preview build.
- Main branch: EAS Build to TestFlight and Google Play internal testing.
- Small JS fixes ship with EAS Update per channel (`preview`, `production`); native changes need a new build.
- Upload source maps to Sentry on every build for readable stack traces.

## Delivery roadmap

&#91;embedded content: roadmap · 5 phases, 2 gates\]

The 3D spike runs in phase 0 because it is the biggest technical risk; if it misses the target, reduce model detail or move the 3D view into a native module. The 2D flow lands first, so users can always book even before 3D is finished.
